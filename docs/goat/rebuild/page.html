## Where the day goes

Past buildouts took a day or more. Most of that
time was not a play running. It was a run stopping
on a defect, the defect being fixed on main, and
the run resuming. Each defect cost a stop, a
diagnosis, a pull request and a resume. The
runtime itself is the second cost.

Rebuild time as a security control.

goat is built so that a whole site can be taken down and built again from its declaration. A site that is rebuilt quickly gives an intruder no lasting place on it, and makes recovery an ordinary operation. This page shows the times measured on real machines, including the target that is not met yet.

What it is

Most defenses try to keep an intruder out, and then to find and remove one who got in. goat adds another control: the time it takes to rebuild. Every site is described by a declaration in a repository. goatbuilder, the command-line tool in goatcore, builds the site from that declaration, checks it against an acceptance suite, and can take it down again. The shorter that cycle is, the less a compromise costs.

A suspected compromise is answered by a rebuild

Cleaning a compromised machine means proving that nothing was left behind. Building it again from the declaration does not depend on that proof. The declaration is signed, every image is named by its content hash, and a deploy refuses anything else.

A foothold lasts only until the next rebuild

An intruder who gains a place on a machine keeps it until the machine is rebuilt. When a rebuild takes minutes, the operator chooses how long that is.

Recovery is the first install, run again

The command that builds a site the first time is the command that rebuilds it. It is timed on real machines and every stop is recorded. A stop caused by the tool becomes a correction to the tool, so the recovery procedure is one that has been run.

A rebuild removes what is on the machines. Three other risks are handled by other parts.

Each line carries the status of the part that does the work.

A rebuild removes

Programs and files left on a machineBuilt The machine is installed again and the stand-up builds it from the declaration: baseline, disk encryption, then every service. The install seed for each class of machine is built and still in trial.
The machine's place on the meshBuilt Each machine enrolls again in phase 8 with a key that works once.
Running services and their containersMeasured teardown --services stops every service of a site and appends a record for each. No earlier record is removed.

A rebuild does not remove

A stolen secret that is still validNot built A stand-up creates the site secrets that are missing and does not replace the ones that exist. Replacing them is a separate, deliberate step, and it is not yet part of a rebuild.
A changed source or imageBuilt A deploy checks the signature on the goatnet's release list, refuses an image that is not named by its content hash, and refuses a tree that differs from the repository. Stop 6 of this run was that refusal.
Data that was already copiedBuilt Shared data can be encrypted for named readers. The platform holds no key, and only those readers can decrypt. This limits what a copy reveals. It cannot recall what a reader has already decrypted.

A fast rebuild makes these properties routine, and each one has a status

A property that depends on a slow rebuild that is rarely practiced is used only in an emergency. With a rebuild that is fast and practiced, the same property is an ordinary operation. Some of these are in use and some are designs.

Built

No site has a public address

A device finds a goatnet through one public name that is answered by relays in a cloud. The relays pass the encrypted connection through without reading it, and joining needs a short-lived key.

Decision record 1192

Built

Each person, machine and workload has its own identity

People and services sign in through the site's own identity provider. A machine holds its own mesh key. A workload gets a certificate from a server that the stand-up installs in phase 9.

Architecture, row 6

Built

The secret store cannot read what it holds

Secrets are encrypted on the person's device before they reach the store. No secret value is kept in a file: files hold references, and a value is resolved for one command at a time.

Built

A deploy refuses a release it cannot verify

Since release 0.8.0 a deploy checks the signed release list and the content hash of every image before it reaches a machine, and updates a later stage only after the earlier one.

goatbuilder

Built

Decoy names and web paths raise an alert on first use

A goatnet can carry decoys that nothing has a reason to use, so any use is treated as hostile. Built for names and web requests. Designed, not built: decoys on the data fabric, and decoy credentials issued by a provider.

deception-layer.md

Designed

A site keeps working when it is cut off

Every site is to keep admitting people, enrolling machines and changing access while it is cut off, and to merge when the link returns. The partition tests are built for mesh control and sign-in. The portal and the administration console are not built for it, and none of the six requirements is measured.

island-mode-multi-writer.md

Designed

The hub can sever a site

The site with the highest authority removes another site from the goatnet. From then on, nothing the removed site writes reaches any other site, and it returns only by being rebuilt and loaded again from the hub. Decided; the work follows release 1.0.

Decision record 1205

Designed

A site is rebuilt from nothing and a checked export

A site, or a whole goatnet, is built again from nothing, using an export of its people, machines and processes that is checked before it is loaded. Proposed; the work follows release 1.0.

Decision record 1237

Built, not enabled

A second key exchange for the mesh tunnels

A key exchange that is designed to resist a quantum computer is built for the tunnels between machines. It is switched off on every goatnet until a defect in it is resolved.

Quick start

A rehearsal of a first site, its teardown and its rebuild, on the fixture in the repository. It needs git and curl. The stand-up and the teardown change nothing outside one temporary directory.

git clone https://github.com/usareur-af/goatcore && cd goatcore
OS="$(uname -s | tr '[:upper:]' '[:lower:]')"; ARCH="$(uname -m | sed 's/x86_64/amd64/; s/aarch64/arm64/')"
curl -fsSL -o goatbuilder "https://github.com/usareur-af/goatcore/releases/download/goatbuilder/v0.8.0/goatbuilder-$OS-$ARCH"
chmod +x goatbuilder
WORK="$(mktemp -d)/zagros"
cp -R ops/goatbuilder/fixtures/goatnet-from-scratch/01-founder "$WORK"
./goatbuilder standup zagros --site alpha --mock "$WORK" --ack "you" --yes
./goatbuilder teardown zagros --site alpha --mock "$WORK"
./goatbuilder standup zagros --site alpha --mock "$WORK" --ack "you" --yes

The stand-up ends with standup: ok (14 checks) and the teardown with teardown: ok (9 checks). On real machines the same commands run without --mock, and print the time of every phase.
