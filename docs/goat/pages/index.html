The system

What goat is: a self-hosted data fabric across sites that keeps working when the network around it fails.

usareur-af.github.io/goatdocs/goat/

goat

A self-hosted data fabric that keeps working when the network around it fails.

goat joins people, machines and services across sites into one network. They publish and subscribe to data, and access is decided by who they are, not where they sit. A device that has joined keeps talking to its peers directly, with or without the cloud.

First screen: goat as one system

Join a goat network

Put a device, a partner's host or an organization on a goat network, and find who to peer with.

usareur-af.github.io/goat-client/

goat-client In development

One signed file, and the device is on the goat network.

A daemon, a desktop GUI and a command line for Linux, macOS and Windows, with iOS, iPadOS and Android shells. It takes a bundle signed by an offline certificate authority, checks the signature, and brings up the outer WireGuard tunnel, the inner NetBird mesh, or both.

First screen: the real daemon, CLI and handshake, replayed

usareur-af.github.io/zagros-moon-pod/

zagros-moon-pod

A small bundle you run on your own host to exchange data with a goat fabric, both ways.

A Zenoh router with mutual TLS that may write only your slot, an observe-only audit sink, and a mesh client on the host. Today it is for learning: rung 2 of the goat learner ladder, joined to the zagros sandbox, not in operational use.

First screen: what crosses the pod router

usareur-af.github.io/saltlick/

saltlick

Advisory, never authoritative. Being listed grants access to nothing.

A directory where an organization publishes its own interconnection capability, so that two organizations can check compatibility before they build a link. It holds signed pointers, not permissions. The reader checks every signature and digest against keys it bound outside the directory.

First screen: a directory session recorded against a real instance

Bring data in, connect other systems

Take data from sensors, wire protocols, network links and vendor systems onto the fabric, and send it back out.

usareur-af.github.io/open-billie/

open-billie

Any sensor in, one track record, three standard formats out.

Open Billie prepares a node, builds a small package for each sensor (a kid), and publishes its data, normalized, as CoT, ASTERIX CAT062 or SAPIENT through Zenoh. The kid decodes; the shared translator writes the format.

First screen: a real frame decoded in the first screen

usareur-af.github.io/first-bite/

first-bite

Binary messages off the wire, decoded, for those you authorise.

It listens on a tap or a mirror port, local or tunnelled (ERSPAN/GRE), decodes fixed-layout binary messages against a dictionary, and publishes each one as a record of typed values. It never transmits on the capture interface.

First screen: a test vector decoded live

Open the pageRepository

usareur-af.github.io/goatrope/

goatrope

Tie distant machines to one link, or tap the link they share.

goatrope takes a copy of one network link, from a tap device, a switch mirror port or its own inline tap on a small computer, and records it, sends on what you name, or relays named datagrams. The relay joins distant sites over the mesh they already share, or through a declared boundary point when a site stands outside it; it is work in progress. One file declares what it does. It runs with nothing else of ours installed.

First screen: a rope figure drawn by build.py, state drawn rather than colored

usareur-af.github.io/scapegoat/

scapegoat

It speaks first, so the sensor starts sending.

Some sensors send nothing until a C2 system talks to them. scapegoat runs on a small computer on the sensor's network and plays that C2 side: it opens the link, keeps it alive and shows whether the sensor is answering. A protocol is a plugin, and the tracks a plugin reads go out as ASTERIX CAT062, CoT or SAPIENT.

First screen: a real session against the toy simulator: the link established, lost and established again

usareur-af.github.io/open-entity-gateway/

open-entity-gateway

Bridges between the goat fabric and vendor systems.

Each bridge is its own package that speaks one vendor's software kit: Anduril Lattice and Picogrid ECN today. A mapping file says how a record becomes a track; the bridge sends it in the vendor's form.

Work on the data

Convert any message format to any other, then correlate, fuse, filter and grade the tracks, with every decision traced.

usareur-af.github.io/goat-transformers/

goat-transformers

Any message format to any other. Every format is a data file.

A drone's 25-byte Remote ID broadcast becomes a Cursor on Target event for a tactical map. No engine holds code for either format: each is a pack, a text file with one line for each field, and seven engines in seven languages read the same packs and must agree byte for byte.

First screen: a conversion played byte by byte by the engine built to WebAssembly

usareur-af.github.io/goat-processors/

goat-processors

Correlation, fusion, filtering and track quality, with every decision traced.

Each function is a written specification, packs of settings and test vectors. Seven engines, written apart in seven languages, reproduce every vector exactly, down to the record of each test they run.

First screen: a test vector replayed step by step on a plan view, with its trace records

Use the data

Route fabric data to the systems that need it, and build on it.

usareur-af.github.io/goatdocs/goat/fieldkit-feeds/

fieldkit-feeds

Send fabric data to the systems that need it, and bring their data in. A tactical admin switches it on.

An operator picks a topic and the system that should receive it, or names what a system sends and the standard it uses. A tactical admin for the site switches the feed on; anyone else's request waits for one. Each feed shows one word for its health, its counters, the exact command it runs and who did what.

Run the estate

Know who owns every cloud resource a deployment uses, what it is for and when it ends.

usareur-af.github.io/goat-cloud/

goat-cloud

Every cloud resource has an owner, a purpose and a lifetime that anyone can look up.

Developers deploy from their own repositories with no central gate and no ticket. Each night a scan finds what has no owner or has outlived its stated expiry; its owner is warned, and it is removed.
