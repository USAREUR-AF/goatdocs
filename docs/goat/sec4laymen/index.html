Our security work, in plain words

We build a private way for a group's computers to talk to each other.

The group can set it up itself, keep it hidden from strangers, and set it up again from a clean start with less than an hour of machine work.

Why it matters

Some people cannot afford to lose touch

Think of the people whose work depends on staying in touch with each other: a rescue team, a hospital, a ship's crew, people working far from home. They share maps, positions, warnings and orders through computers.

Two things can go badly wrong. A stranger can break in, and then read what is sent, change it, or shut things off. Or the connection to the outside world can be cut, and everything that depended on it stops.

Most designs guard against the first problem with a strong front gate, and have no answer to the second. Our team's work is a different design. It is hard to find, it checks everyone every time, it keeps what is sent locked, it is designed to keep working when it is cut off, and if something does go wrong it can be wiped and set up again quickly.

In one sentence

We make it hard to break in, and quick to start again clean if someone does.

First, five ordinary words

Computers send each other letters

A program is a set of instructions that a computer follows, the way a cook follows a recipe.

A message is anything one computer sends to another: a line of text, a position on a map, a photograph, a reading from an instrument. You can think of each message as a letter.

A computer network is a group of computers that can send messages to each other, the way houses on connected streets can send each other letters.

The internet is the largest network there is: the public streets that almost every computer in the world shares.

A server is a computer whose job is to run programs for many other computers. It is to a network what a post office is to a town.

In one sentence

A network is streets, computers are houses, and messages are letters.

Locks and keys

Locking a message, and the difference between unlocking and translating

Encryption is scrambling a message so that it looks like nonsense to everyone except the person meant to read it. It is the same idea as putting a letter in a locked box. On this page, when we say a message is sealed, we mean it is encrypted.

A key is what opens the box. On a computer a key is a very long secret number. Whoever has the right key can open the box. Nobody else can.

To decrypt a message is to unlock it with the key and read it.

To decode a message is something different, and people often confuse the two. Decoding is translating. Different machines write the same information in different ways, like people writing in different languages, and decoding turns one machine's way of writing into another's. No secret is involved. Anyone who knows the language can decode. Only the holder of the key can decrypt.

In one sentence

Decrypting is unlocking with a secret key; decoding is translating, and needs no secret.

A private route

Our network is a sealed route laid across the public roads

Messages have to travel over something. A link, also called a transport, is whatever carries them: a cable in the ground, a mobile phone network, a satellite.

The underlay is the name for those shared links taken together. It is the public road system that everyone uses.

An overlay is a private route laid across those public roads. The letters still travel on the same roads as everyone else's, but each one is locked, and only the houses that belong to the route can open them. The network our team builds is an overlay, and it can ride on any link that is available.

In one sentence

We do not build new roads; we build a private, locked route across the roads that already exist.

Hidden

A house with no door on the street

Most of what you use on the internet, such as a shop's website, has a public address. It is like a shop with a door on the street: anyone can find it, walk up and try the handle.

The computers in our network have no door on the street. If a stranger sends one of them a message, it does not reply at all, not even to say no. A stranger who goes looking finds nothing that answers.

There is one exception, and it is on purpose. A new computer needs some way to join, so the network has a single public name that is used only for joining. The newcomer must present a key that works one time. After that it talks to the other computers directly, and the name is not used again.

In one sentence

A stranger who knocks gets no answer, because there is no door to knock on.

Your own computers

Everything that matters stays on computers you own

A site is one place and the group of computers there: an office, a vehicle, a camp.

In our design, each site runs everything it needs on its own computers, which its owner holds and controls. The information stays there.

Sometimes two computers cannot reach each other directly. Then a relay helps. A relay is a rented computer somewhere on the internet that passes sealed letters along. It is like a courier who carries a locked box from one house to another. The courier has no key, so the courier cannot read what is inside or change it, and any courier can be replaced by another.

In one sentence

Rented computers only carry locked boxes; the keys and the contents never leave your own machines.

Checking everyone, every time

No inside and no outside

Many networks work like a building with one guard at the front door. Once you are past the guard, every room is open to you. If a stranger gets past the guard once, the stranger can go everywhere.

Ours works like a building where every single door checks your badge, every time. Being inside the building earns you nothing.

The badge is called an identity: proof of exactly who or what is asking. A person has one. So does each computer, and so does each program.

This approach has a name, zero trust. It means that nothing is trusted because of where it is. Each time one thing wants to talk to another, four questions are asked. Who is asking? Is there a written rule that allows these two to talk? Is this particular action allowed? Is the badge still good, or has it been taken away? If any answer is no, nothing happens.

In one sentence

There is no trusted inside to sneak into, because every door checks every visitor.

More than one lock

A message is locked for the journey, and can be locked again for its readers

Every message between two of our computers travels inside a lock that only those two computers can open.

Sensitive information can get a second lock. The owner seals it for a named list of readers, and only those readers hold keys. The computers that carry and store it in between hold no key at all. That includes the servers that our own programs run on.

The same is true for the place where secrets such as passwords are kept. A secret is locked on your own computer or phone before it is stored, so the store cannot read what it is holding.

In one sentence

If someone steals a server, what they get is a pile of locked boxes.

Nothing unchecked runs

Every program is checked before it is allowed to start

Programs are written by people as text. A build turns that text into a program a computer can run, the way baking turns a recipe into bread.

A release is one finished, numbered version of a program that is ready for others to use.

An image is a complete, packed copy of a program with everything it needs, ready to run. Think of a sealed package from a factory.

A deployment is the act of putting a program onto the computers where it will run.

Before anything is put onto a computer, it is checked the way you would check that sealed package. Is the maker's seal on it, and is the seal real? Are the contents exactly what the label says, with nothing added or swapped? If either check fails, the program is refused and never starts.

In one sentence

A program that has been tampered with is refused before it reaches a single computer.

A problem from the future

Locked messages copied today could be opened years from now

A new kind of computer, called a quantum computer, is being developed. It is expected to be able to break some of the locks that protect messages today.

That creates a danger now, not only later. Someone can copy locked messages today, keep them, and wait. This is called harvest now, decrypt later. For information that must stay private for many years, a lock that will fail in ten years is already not good enough.

Post-quantum locks are designed to hold even against such a computer. Our design uses two locks together: the usual kind, and a post-quantum kind. To read the message, someone would have to break both.

Where this stands: the two locks together are working today on the part of the network that delivers messages between programs. For the connections between computers it is built and not yet switched on. For connections between different organizations it is planned.

In one sentence

We add a second lock that is built to hold against the code-breaking computers of the future.

Decoys

A door that leads nowhere, and rings a bell

A decoy is something that looks real and useful but that nobody has any reason to touch: a name or an address that leads nowhere.

The people and programs that belong on the network never go near a decoy. So when someone does touch one, there is only one explanation. An alarm goes to the person on duty at once.

Ordinary alarms have to notice something unusual among everything normal, so a quiet intruder can go unseen for a long time. An alarm from a decoy is never set off by normal work.

Where this stands: decoy names and addresses are built. More kinds of decoy are planned.

In one sentence

Anyone who tries a decoy door has told us they do not belong.

Starting again clean

A whole site can be wiped and set up again with less than an hour of machine work

If your phone behaves strangely and you suspect something bad is on it, the surest fix is to erase it and set it up again from a clean start. Cleaning it by hand leaves you wondering what you missed.

For a whole site full of computers and programs, starting again has always been slow and painful: days of work, done rarely, by a procedure nobody has practiced. So people avoid it, and an intruder who got in stays in.

In our design, a site is fully described by a written plan. A rebuild means setting the whole site up again from that plan. One instruction does it: it prepares the computers, locks what is stored on them, starts every program, connects the site to the network, and then runs a set of checks to prove that everything works.

38 minutes 12 secondsof machine working time to set up a whole site, measured on real computers
5 minutes 54 secondsto take a site down, measured on real computers

Where this stands: both times above are measured. The team's requirement for its next major version is the whole job, from start to finish with no pauses, in 60 minutes or less. The team is working toward that now.

In one sentence

When in doubt about a machine, we do not clean it; we rebuild it, and that takes minutes, not days.

Cut off, and still working

A site keeps working when its connection is cut

Picture a town with its own generator and its own well. When a storm takes down the lines to the rest of the country, the lights stay on.

A site in our design is meant to be like that town. Each site carries everything it needs. If its connection to the other sites is cut, the people there keep working.

This has a second benefit. A site that does not depend on a long connection does not have to send anything outward at all. A site that is silent is much harder for anyone to find.

One more piece is planned. If a site can no longer be trusted, the main site can cut it away from the others. From then on nothing it sends reaches anyone else, which protects the rest. But the site that was cut away is not shut down. The people there keep their own systems and keep working. It comes back only after it has been rebuilt.

Where this stands: this part is planned. Pieces of it are built and tested.

In one sentence

Losing the connection does not stop a site, and protecting everyone else does not mean destroying one part.

Open to inspection

Anyone can read how it works

All of this work is published. The instructions, the designs and the tests are public, and anyone may read them, use them and check them.

That can sound backwards. Would it not be safer to keep it secret? A lock is only good if it still holds when everyone knows exactly how it is made. Only the keys are secret. Showing the design lets many more people look for weaknesses and tell us, which makes the work stronger.

For readers who want the technical detail, the same ideas are on the security page, with figures, the measurements, and links to the code.

In one sentence

The design is public; only the keys are secret.
