security

Hard to get into. Easy to rebuild.

goat is hardened against intrusion at every connection. It is also built so that a whole site can be taken down and rebuilt from its declaration in minutes. A rebuild is an ordinary, practiced operation here, not a painful reaction to a disaster, and it returns every machine to a known clean state.

No inside, no outside

Known as: zero trust, microsegmentation, deperimeterization

Usually
Most defenses draw a few boundaries, sometimes only one, and those boundaries move slowly or never. Anything that gets inside one is trusted there.
Here
goat draws none. Each connection between two parties, whether people, machines or programs, has its own keys and its own rule, set by who the two are and what they are doing. When either changes, the protection on that connection changes with it.
For you
There is no trusted zone to get into.

Five habits that make a network easier to find, easier to enter and slower to recover

Known as: attack surface, single point of failure, signature management

Each one is common, and each one has a cost. goat is a private mesh overlay, hidden from the public internet, that is built without them.

{{MARK_OUTSIDE}}

A door on the public internet

A service or a gateway that anyone can reach is one that anyone can probe.

in useNo service has a public address. The private overlay does not answer what it cannot authenticate.

{{MARK_ZERO_TRUST}}

Trust by location

Whatever gets inside a boundary is trusted there.

in useThere is no inside. Every connection has its own keys and its own rule.

{{MARK_ISLAND}}

A distant center

A far cloud and a long link back to it: cut the link and the site stops, and the link can be found and followed.

in useEach site runs everything it needs on its own machines, and its machines keep talking with no link.

designedAdministration changes at a cut-off site.

{{MARK_ORDINARY}}

Special parts

Special encryption, special lines and special hardware mark who is there, and take months to replace.

in useOrdinary computers, a common open protocol, and any link that carries packets.

{{MARK_REBUILD}}

Recovery as a rare emergency

A compromised system is cleaned in place and restored slowly, by a procedure that nobody practices.

measuredA whole site is rebuilt from its declaration in minutes, as a routine operation.

{{SCENE_CUSTODY}}
{{MARK_OUTSIDE}}

Little to find: joining

Joining happens once, through the only public name

Known as: overlay network, software-defined perimeter, attack surface reduction

Usually
Services have public addresses, protected by a filter and a login page. Anyone can find them and test them.
Here
A goatnet has one public name, and it is used only to join. A relay behind the name passes the encrypted connection to the site and cannot read it.
For you
Only one name of yours is public, and it is used only to join.
  • in use"No host site has a public address." goatcore, decision record 1192

Little to find: after joining

After joining, devices talk directly and nothing is public

Known as: peer-to-peer mesh, overlay network, attack surface reduction

Usually
Traffic goes through a central gateway with a public address, and the gateway must stay up.
Here
Devices that have joined connect to each other directly over the mesh (NetBird, which sets up WireGuard tunnels), each connection encrypted by itself. A relay is used only when two devices cannot reach each other, and it carries traffic it cannot read.
For you
An outside observer sees only encrypted packets, and your devices keep talking when the admitting service is unreachable.
  • in use"devices that have already joined keep talking" goatcore, decision record 0201
{{MARK_SILENT}}

A quiet, ordinary protocol

A scan finds nothing listening

Known as: traffic analysis resistance, low probability of detection, attribution

Usually
Encryption made for one kind of user has its own equipment, ports and handshakes. Seeing it on a network says who is there.
Here
The overlay's tunnels between machines use WireGuard, an open protocol that many ordinary VPN users also use, so its traffic does not mark the sender as a government system. A machine does not answer a packet that it cannot authenticate.
For you
A stranger who probes your address gets no reply to learn from.
  • in use"The server does not even respond at all to an unauthorized client; it is silent and invisible." wireguard.com, Protocol
{{MARK_ZERO_TRUST}}

Zero trust

Being on the network grants nothing

Known as: zero trust architecture (ZTA), least privilege, mutual authentication, policy as code

Usually
A device inside the network is trusted because of where it is.
Here
Every request passes four checks: who is asking, whether a declared rule allows the connection, what the role may do, and whether the identity is still good. With no rule there is no connection.
For you
Access is written down in one place that you can read, review and change.
  • in useidentities; declared rules, applied and checked by every stand-up
  • builtthe table of roles, revocation, review
{{MARK_SEALED}}

Sealed data

One stolen server does not open everything

Known as: zero-knowledge storage, client-side encryption, end-to-end encryption

Usually
A secret store can read every secret it holds, and a message broker can read every message. Whoever takes that server has all of it.
Here
A secret is encrypted on your device before it is stored, so the store cannot read it. Shared data on the data fabric (Zenoh) is sealed once, and its key is sealed separately for each named reader.
For you
A stolen server holds only sealed data.
  • in usethe secret store; no central broker; sealing for named readers, in use for the data sets an owner seals

{{MARK_VERIFIED}}

Verified releases

Nothing runs unless it is verified

Known as: software supply chain security, signed provenance, content addressing

Usually
A machine runs whatever was last installed on it, and an image name can point to different content over time.
Here
A signed list says which release runs where, and every image is named by its content hash. Before a deploy changes a machine, it checks the signature, the hash, the source and the order of stages.
For you
A changed image or an edited configuration is refused before it reaches a machine.
  • in usegoatbuilder 0.8.0: each refusal has an error code, and goatbuilder explain <code> gives the cause and the fix
{{SCENE_SELF_DOCUMENTING}}
{{MARK_QUANTUM}}

Post-quantum

Traffic recorded today stays closed later

Known as: post-quantum cryptography (PQC), hybrid key exchange, harvest now, decrypt later

Usually
Encrypted traffic can be recorded now and kept. A future quantum computer could open what today's key exchange protects.
Here
The routers of the data fabric prefer a combined key exchange: the usual kind together with one built to resist a quantum computer. A client that supports the combination gets it, and reading that traffic means breaking both.
For you
Data that must stay private for years is protected against a later reader.
  • in usethe data fabric
  • builta post-quantum key exchange for mesh tunnels, not enabled
  • planneda standardized post-quantum key exchange for mesh tunnels; options are being evaluated
  • designedlinks between organizations
{{MARK_DECOY}}

Decoys

A decoy raises an alarm on its first use

Known as: deception technology, honeytokens, canaries

Usually
Detection depends on noticing unusual behavior among normal use, so quiet exploration can go unseen for a long time.
Here
A site carries decoys: names and web paths that no person or program has a reason to use. Any use of one is hostile, and the first use alerts the operator on call.
For you
An alert from a decoy means an intruder. Normal use never touches one.
  • builtdecoy names and web paths
  • designeddecoys on the data fabric, decoy credentials

{{MARK_REBUILD}}

Rebuild

A rebuild returns every machine to a known clean state

Known as: immutable infrastructure, infrastructure as code, cyber recovery

Usually
A compromised machine is cleaned in place, and the cleaning is trusted. A full rebuild takes days, so it is avoided.
Here
A site is described by a declaration in a repository. One command builds the whole site from it, and the same command builds it again.
For you
A rebuild is an ordinary, practiced operation, not a painful reaction to a disaster. When you have a doubt about a machine, you rebuild it.

{{MARK_ISLAND}}

Sites that stand alone

Cut off, a site keeps working, and it can stay silent

Known as: disconnected operations (DDIL), local-first, partition tolerance, emission control

Usually
Sites depend on a long link to a central service. When the link fails they stop, and while it works it can be found, jammed or followed.
Here
Every site runs the same services and keeps working while it is cut off. A site that needs no link back does not have to transmit off-site at all.
For you
A lost link does not stop a site, and a silent site is harder to find.
  • in usemachines that have joined keep talking to each other with no link to any other site
  • builteach site runs its own sign-in and mesh control, both tested with the link cut
  • designedchanges made in the portal and the administration console at a site that is cut off, merged when the link returns
{{MARK_HUB}}

A severed site

Severed, a site works alone

Known as: isolation, containment, cyber recovery

Usually
A site that may be compromised stays connected, or it is shut down and its people lose their systems.
Here
The hub can sever a site that it no longer trusts, and nothing that site writes then reaches any other site. The severed site keeps running locally, and rejoins only after it is built again and loaded from the hub.
For you
You protect the other sites without switching off the severed one.
  • builtthe hub's sever directive: nothing a severed site writes reaches another site, tested with the link cut
  • designeda severed site rejoins after it is built again and loaded from the hub
{{SCENE_BOUNDARY}}

Where each part stands

Measured: a named run on real machines. In use: built and running by default. Built: in the tree, and not switched on by default. Designed: decided, and not built. Planned: intended, with options being evaluated.

Try it

Build a site, take it down and build it again, on the example in the repository. It needs git and curl. The build and the teardown change nothing outside one temporary directory.

git clone https://github.com/usareur-af/goatcore && cd goatcore
OS="$(uname -s | tr '[:upper:]' '[:lower:]')"; ARCH="$(uname -m | sed 's/x86_64/amd64/; s/aarch64/arm64/')"
curl -fsSL -o goatbuilder "https://github.com/usareur-af/goatcore/releases/download/goatbuilder/v0.8.0/goatbuilder-$OS-$ARCH"
chmod +x goatbuilder
WORK="$(mktemp -d)/zagros"
cp -R ops/goatbuilder/fixtures/goatnet-from-scratch/01-founder "$WORK"
./goatbuilder standup zagros --site alpha --mock "$WORK" --ack "you" --yes
./goatbuilder teardown zagros --site alpha --mock "$WORK"
./goatbuilder standup zagros --site alpha --mock "$WORK" --ack "you" --yes

The build ends with standup: ok (14 checks) and the teardown with teardown: ok (9 checks). On real machines the same commands run without --mock and print the time of every stage.
