Joining

A device that joins presents a key that works once. It then gets its identity and the list of parties it may reach.

Services have names that exist only inside the goatnet. The service that admitted a device is not in the path of that device's traffic afterward.

The four checks

CheckWhat it means
Who is askingA person, a machine and a program each prove their identity in their own way.
Is there a ruleA connection needs a declared rule. With no rule there is no connection.
Is it allowedA declared table says what each role may do.
Is the identity still goodAn identity can be revoked, and a machine can be held for review.

The rules in force are generated from a declaration that is reviewed like code. A partner's identities can be verified without being granted anything.

Sealing for several readers

The owner seals a data set once. The key that opens it is then sealed separately for each named reader, with that reader's own key.

So several readers can open the same data, each with a different key. A reader can be added or removed without changing anyone else's key.

The platform holds no key for sealed data. The data fabric that carries it holds no key and has no central broker.

Post-quantum key exchange

The routers of the data fabric prefer the combined key exchange. A client that does not support it connects the usual way.

For mesh tunnels a post-quantum key exchange is built and not enabled. A standardized post-quantum key exchange for mesh tunnels is planned, and options are being evaluated.

A site that is cut off

A site that is cut off keeps admitting people, enrolling machines and changing access. This part is designed; the tests for mesh control and sign-in under a cut link are built.

A site that sends nothing off-site gives less to find in the radio spectrum, to signals collection and on the network.
