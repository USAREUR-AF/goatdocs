goatbuilder

One tool for every machine in a goatnet, from the core servers to the billie kids.

Declare what a machine is for. goatbuilder takes it from a reachable Ubuntu host to its role in the goatnet, then checks the result. Five roles build today. Eight more, from boundaries to processing to the network tap, are designed as target types, with a place for a role of your own.

Roles

Pick what the machine is for.

A target type is the job a machine does. In the design, each is one file: the hardware it accepts, the encryption it requires, its plays in order, its services and its acceptance checks. A new role is a new file. It needs no new code in goatbuilder.

What a role looks like as data

The sketch from the design, for break-glass. It names a hardware family, never a model, so new hardware joins a family without touching any role.

Software with its own repository keeps its own installer. The type file names the repository and release, and goatbuilder calls that installer at a pinned, signed release and checks what it did.

The design and ADR 1257, under review

# ops/goatbuilder/targets/breakglass.yaml (designed)
type: breakglass
families: [small-computer]
encryption: root
os:
  - ubuntu: "24.04"
plays:
  - play: mgmt-host-baseline.yml
  - play: breakglass-nodes.yml
    group: "{site}_breakglass_hosts"
services: [netbird-client, oob-overlay]
acceptance:
  requires: [breakglass]
proof:
  ci: vm
  hardware: required

At the sensor

One kid per sensor, and a Billie node to run them.

A billie kid is one small package for one sensor. It decodes and maps that sensor's data. The Open Billie platform under it encodes, routes and secures what the kids produce, so a kid holds no fabric credentials.

A drawing of what one node can run. scapegoat and first-bite are optional services with their own outputs. Designed: the machine's declaration lists its sensors, and goatbuilder installs the platform at a pinned, signed release, then installs, configures and activates each sensor's kid with Open Billie's own commands. Today Open Billie's guided install does this, and first-bite and scapegoat have their own installers.

sudo billie kid install <bundle>
sudo billie kid configure <id>
sudo billie kid activate <id>

The same pattern holds for all three: a public core, and a private overlay for what cannot be public. A sensor owner's decoder, dictionary or protocol stays in their own repository.

Services

A machine has a role. Services run on it.

A role says what a machine is. A service says what runs there: a version, a play, a health check. goatbuilder deploy moves one service to one environment and is done only when every machine's own ledger names the declared version.

The network tap

A tap must not break the link it listens to.

A small computer that bridges two network ports is in the link: when it stops, the link stops, and no software changes that. So the role makes every machine declare how it is connected.

listen: fails open

A passive copper tap, a bypass relay or a switch mirror port carries the link. If the machine stops, only the recording has a gap.

inline: fails closed

Built only when the declaration names who accepted that the link drops with the machine. doctor and status print it on that machine.

Designed, not built. The capture software is first-bite.

Your own

A private role needs no public change.

Put the type file in your overlay and the plays in your own repository. goatbuilder fetches them on your machine with your access, checks the pinned digest and signer, and holds them to the same checks as a public role. Public code, documents and releases never name it. Designed.

Try it

Build a whole example site on your laptop.

The rehearsal uses a simulated set of machines and touches no network. It builds three roles: core, obs and break-glass.

git clone https://github.com/usareur-af/goatcore && cd goatcore
OS="$(uname -s | tr '[:upper:]' '[:lower:]')"; ARCH="$(uname -m | sed 's/x86_64/amd64/; s/aarch64/arm64/')"
curl -fsSL -o goatbuilder "https://github.com/usareur-af/goatcore/releases/download/goatbuilder/v0.7.3/goatbuilder-$OS-$ARCH"
chmod +x goatbuilder
WORK="$(mktemp -d)/zagros"
cp -R ops/goatbuilder/fixtures/goatnet-from-scratch/01-founder "$WORK"
./goatbuilder standup zagros --site alpha --mock "$WORK" --ack "you" --yes
./goatbuilder status --env zagros --mock "$WORK"

Each release lists a SHA-256 checksum per binary in SHA256SUMS, signed with cosign. Next: a new goatnet, step by step, or the goatbuilder book.

What is next

One foundation, then four lanes at once.

The design makes every role a requirement of goatbuilder 1.0. Every role must pass in CI, on a virtual machine started from a fresh cloud image. Where there is equipment, it must also pass a recorded run on hardware.

Foundation. The role and hardware-family files and their reader, the base check of doctor --target, and the CI harness that builds on virtual machines.
Host sitecore and obs read from type files; standup with no manual step
Boundaryfederation boundary, simple boundary
Processinggoat-processors, accepted when its engines reproduce their conformance vectors
Small computerthe builder first, then break-glass, jump box, Billie node, octo-pod, vendor gateway, first-bite, network tap

A fifth lane, services, starts with software that ships as a signed file instead of an image.
