goatbuilder

One tool for every machine in a goatnet, from the core servers to the sensor node.

Declare what a machine is for. goatbuilder takes it from a reachable Ubuntu host to its role in the goatnet, then checks the result. Five roles build today. Seven more, from boundaries to processing to the edge, are designed as target types.

Roles

Pick what the machine is for.

A target type is the job a machine does. In the design, each is one file: the hardware it accepts, the encryption it requires, its plays in order, its services and its acceptance checks. A new role is a new file. It needs no new code in goatbuilder.

What a role looks like as data

The sketch from the design, for break-glass. It names a hardware family, never a model, so new hardware joins a family without touching any role.

Software with its own repository keeps its own installer. The type file names the repository and release, and goatbuilder calls that installer at a pinned, signed release and checks what it did.

The design and ADR 1257, under review

# ops/goatbuilder/targets/breakglass.yaml (designed)
type: breakglass
families: [small-computer]
encryption: root
os:
  - ubuntu: "24.04"
plays:
  - play: mgmt-host-baseline.yml
  - play: breakglass-nodes.yml
    group: "{site}_breakglass_hosts"
services: [netbird-client, oob-overlay]
acceptance:
  requires: [breakglass]
proof:
  ci: vm
  hardware: required

From the metal

It checks where a machine ends up, whatever path it took.

Above the line, goatbuilder builds

Baseline and joinHardening, WireGuard modules, a single-use setup key, the mesh address recorded. Built.
Install the roleThe role's services, deployed over the mesh. Built for five roles.
Prove itAcceptance checks that must pass, never “unknown”, written to the machine's own ledger. Built; the break-glass and jump box checks are designed.
a reachable Ubuntu host with an SSH key

Below the line, it guides and checks

On known hardwaregoatbuilder image <model> runs that model's builder: numbered steps from blank media, each proving its result. Designed.
On anything elseWritten directions that state the intent and the end state, for a capable person to follow. Designed.
Either waygoatbuilder doctor --target <type> reads the host, changes nothing, and names what to fix on the machine. Designed.

Try it

Build a whole example site on your laptop.

The rehearsal uses a simulated set of machines and touches no network. It builds three roles: core, obs and break-glass.

git clone https://github.com/usareur-af/goatcore && cd goatcore
OS="$(uname -s | tr '[:upper:]' '[:lower:]')"; ARCH="$(uname -m | sed 's/x86_64/amd64/; s/aarch64/arm64/')"
curl -fsSL -o goatbuilder "https://github.com/usareur-af/goatcore/releases/download/goatbuilder/v0.7.3/goatbuilder-$OS-$ARCH"
chmod +x goatbuilder
WORK="$(mktemp -d)/zagros"
cp -R ops/goatbuilder/fixtures/goatnet-from-scratch/01-founder "$WORK"
./goatbuilder standup zagros --site alpha --mock "$WORK" --ack "you" --yes
./goatbuilder status --env zagros --mock "$WORK"

Each release lists a SHA-256 checksum per binary in SHA256SUMS, signed with cosign. Next: a new goatnet, step by step, or the goatbuilder book.

What is next

One foundation, then four lanes at once.

The design makes every role a requirement of goatbuilder 1.0. Every role must pass in CI, on a virtual machine started from a fresh cloud image. Where there is equipment, it must also pass a recorded run on hardware.

Foundation. The role and hardware-family files and their reader, the base check of doctor --target, and the CI harness that builds on virtual machines.
Host sitecore and obs read from type files; standup with no manual step
Boundaryfederation boundary, simple boundary
Processinggoat-processors, accepted when its engines reproduce their conformance vectors
Small computerthe builder first, then break-glass, jump box, sensor node, octo-pod, vendor gateway, first-bite
