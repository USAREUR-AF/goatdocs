goat

A self-hosted data fabric that keeps working when the network around it fails.

goat joins people, machines and services across sites into one network. They publish and subscribe to data, and access is decided by who they are, not where they sit. A device that has joined keeps talking to its peers directly, with or without the cloud.

What it is

One network across sites. No central broker. Access by identity.

goat is an integration of established open-source projects, assembled and operated as one system. A goatnet is one environment: its own mesh, identity service, certificate authority and data fabric. Two command-line tools come with it: goatbuilder builds, releases and deploys a goatnet, and goat operates one.

Nothing sensitive faces the internet

Every service listens only inside the encrypted network. The public internet sees DNS records, not open ports.

Joined devices keep working when the center goes down

The management service is needed to enroll a device, not to keep it connected. If it fails, peers carry on talking to each other.

There is no central data broker to lose

Data moves between publishers and subscribers directly, so no single server stands between them.

ConcernBuilt on
NetworkWireGuard peer-to-peer tunnels, managed by NetBird, with relays for peers that cannot reach each other directly
DataEclipse Zenoh publish/subscribe with no central broker
IdentityOry for people and services, SPIFFE for workloads, an offline certificate authority for machines
Site statePostgreSQL, replicated active-active between sites

The parts

Five repositories, one system.

goatcore is the substrate. goatstuff looks at it. open-billie and octo-pod bring data onto it from equipment that is not goat. goatdocs explains it. Only goatcore is needed to run a goatnet.

goatcore

The substrate

The code that builds and runs a goatnet: the mesh control plane, the Zenoh data fabric, identity, the goat and goatbuilder command-line tools, and the Ansible roles and Terraform modules that deploy them. Machines pull their configuration and report what they run; a deployment is finished when every report matches the declaration.

goatstuff

Inspection and demos

Inspection tools and demonstration applications that run on a goat data fabric: panoscope (the whole goatnet at a glance), stethoscope (health), flashlight (who did what, when), netvis (the mesh access rules as a picture), and example applications. None of it is needed to run a goatnet.

open-billie

Sensor node

The data path, from the open-billie README. A diagram, not a capture. The figure scrolls sideways.

A sensor-neutral platform for one node beside a sensor. A kid package holds one sensor's decoder, schema and mapping; the shared translator turns its records into Cursor-on-Target, ASTERIX CAT062 or SAPIENT and publishes them through Zenoh. The platform owns the fabric credentials, so a kid package needs none.

octo-pod

Edge gateway

What crosses, both ways, from the octo-pod README. A diagram, not a capture. The figure scrolls sideways.

An edge gateway appliance on one small computer where sensors live. It takes in their feeds, records and audits them locally, and releases only what you choose onto the fabric. It works the other way too: it delivers data from the fabric to a local receiver. Every feed gets its own certificate and a narrow set of keys. Nothing on the running pod changes until you apply.

Install release 0.6.0 from your laptop

$ tools/install-to-pod.sh operator@192.0.2.10 --version 0.6.0 --with-images

First hour

Rehearse on your laptop, then stand up one machine.

This is the path the goatcore README and its first tutorial give. The rehearsal touches no network. The tutorial says the real run takes an hour or more and asks you not to plan around a number.

  1. Get the code and the builder

    Clone goatcore and download goatbuilder for Linux or macOS. Each release lists a SHA-256 checksum per binary, signed with cosign.

    git clone https://github.com/usareur-af/goatcore && cd goatcore
OS="$(uname -s | tr '[:upper:]' '[:lower:]')"; ARCH="$(uname -m | sed 's/x86_64/amd64/; s/aarch64/arm64/')"
curl -fsSL -o goatbuilder "https://github.com/usareur-af/goatcore/releases/download/goatbuilder/v0.7.3/goatbuilder-$OS-$ARCH"
chmod +x goatbuilder

  2. Rehearse a complete standup

    goatbuilder stands up the example goatnet zagros against a simulated set of machines: one site with two core machines, one monitoring machine and one recovery machine.

    WORK="$(mktemp -d)/zagros"
cp -R ops/goatbuilder/fixtures/goatnet-from-scratch/01-founder "$WORK"
./goatbuilder standup zagros --site alpha --mock "$WORK" --ack "you" --yes
./goatbuilder status --env zagros --mock "$WORK"

  3. Stand up goatlite on one machine

    goatlite is a goatnet on one Ubuntu 24.04 host or virtual machine with 4 cores and 16 GB, with no outside account. You write one file of four facts (a name, the host, the SSH user, the administrator), check your laptop with the doctor, and run one command. It is for learning and first goatnets, not for production.

    goatbuilder doctor
goatbuilder standup pasture

    Tutorial 0: your first goatnet explains each step. You finish by publishing a message and receiving it.

  4. Carry on

    A new environment on real hardware, a second site, and sharing with a partner. When a command fails, paste its output into goat explain.

    $ ./goatbuilder explain GB-001

  fix:  grep -n '^  [a-z0-9-]*:' ops/pins/fleet-pins.yaml | head -60

Take part

Build on the stable line. Contribute to main.

goat is pre-1.0: interfaces can still change between releases.

Build on it

Use the stable branch of goatcore or the goatcore/v tag it points at. How the two lines fit together.

Change it

Open a pull request against main. Read CONTRIBUTING first; every CI check is a script under ops/ci/ that you can run locally.

List what you built

Work that other people and organizations build on goat is listed in awesome-goat. Add yours there.

Report a vulnerability

Privately, as described in SECURITY. Not in a public issue.
