goat

One command-line tool to operate a goatnet: its health, who is on it, and its data.

goat answers the questions an operator asks about a running goatnet. Is it healthy? Is data flowing? Who is on it, and what may they do? Why is this connection blocked? It is one file per platform, it runs with your own certificate, and it starts in a sandbox that needs no credentials and no network.

Star on GitHubTry itEvery verb

OS="$(uname -s | tr '[:upper:]' '[:lower:]')"; ARCH="$(uname -m | sed 's/x86_64/amd64/; s/aarch64/arm64/')"
base=https://github.com/usareur-af/goatcore/releases/download/goat-cli-v0.5.20
curl -fsSL -o goat "$base/goat-$OS-$ARCH" && chmod +x goat
./goat hello

What it is

One operator binary over the whole fabric.

It starts in a sandbox

goat hello and goat tutor run against a simulated fabric inside the binary. Every simulated line is marked ◇ SANDBOX. The tutor has 11 lessons, saves your place, and ends where a real goatnet begins.

It reads; it does not guess

Health that cannot be measured reads unknown or unmetered, never green. Each row names the observer that produced it. An empty check fails instead of passing.

It is safe to script

The reading verbs take --json; top and who take --once for one plain frame. The interactive screens need a terminal and refuse a pipe. Exit codes are fixed: 3 profile, 4 portal refused or unreachable, 5 off the mesh, 6 certificate.

goat and goatbuilder come with every goatnet. goatbuilder builds the machines and deploys the services. goat operates what goatbuilder built: it reads the goatnet, changes who is on it, and moves data on it.

Health

It says unmetered when it cannot see.

goat top is one screen for the whole goatnet: a line of health per domain, the load per fabric class, and the producers ranked by rate, refreshed as beats arrive. It only reads what the goatnet already publishes. A domain with no beat reads UNMETERED n=0; a stale beat shows its age and hides its bars.

goat health --domain <d> reads one domain in depth, and --watch keeps reading. The domains:

goat status asks whether you are connected: the router port, a real mTLS session to the router, the portal, and your certificate's expiry, one line per check. Trust the session line over the port line; a stuck router still accepts a TCP connection.

goat flow asks whether data is flowing and when it last did, per topic. It keeps three answers apart: no observer could answer; an observer looked back over a stated horizon and found nothing; data is flowing. It never claims a topic has never published.

Who

One roster across the identity layers.

goat who lists every identity on the goatnet, declared and live, and shows for each one what it may do and what it is doing. Select a row and the detail pane rolls the layers into one view: identity, mesh, data and release. A read grant says an identity may read; a live subscription says it is reading. goat keeps the two apart.

Solid: the layers goat who joins today. Dashed: SPIRE and SPIFFE workload identity, designed as the fourth layer. The figure scrolls sideways.

on-meshEnrolled on the mesh, not connected now.

no-grantsOnboarded with no write or read grant. Its requests are refused without a reply.

For a stray or a cut-off identity the detail pane prints the goat admin command that would act on it. goat who itself changes nothing.

Access

Ask why a connection is blocked before you touch the network.

The fabric refuses a denied request without telling the party it refused, so a denial looks like a broken link. goat answers access questions from the declaration in git, with no network and no credentials. When the gap is real, goat warrant why-blocked names the smallest port-set that closes it and prints the change to propose.

goat access asks the same of data: who (what may this identity write and read, with the reason at each layer), topic (who may write and read this topic), why (one allow or deny traced across mesh, identity, Zenoh ACL and release) and strays (every live identity with no declared match, grouped by why).

Errors

Every error says what happened, why, and what to do.

Each error goat prints says what happened, the likely cause, what to do (a command where one exists) and where to read more, and most carry a code. The words a called tool leaves behind, such as ssh, are interpreted the same way. One catalog in goatcore, ops/errors/catalog.yaml, is compiled into both goat and goatbuilder, so goat explain works offline and with no checkout.

$ goat explain E_NOT_ADMINE_NOT_ADMIN — an operator-only action without operator authority  what: a `goat admin` action was refused, client-side (no operator credentials in the profile) or by the portal/NetBird API (HTTP 403, nothing changed).  why:  the profile is using the vp_ participant token, not the op_ operator key        the role is not authorized for this action  fix:  GOAT_PORTAL_TOKEN=op_… goat admin …        goat admin operator-key request --reason …   (when you hold no op_ key)  read: docs/design/platform-admin-lifecycle.md  exit: 4

An operator-only action without operator authority changes nothing and exits 4. Real output of goat explain E_NOT_ADMIN, goat 0.5.20.

Any pasted error text, matched against the catalog. When nothing matches, goat explain --report - writes the text to a file to share, so the catalog can grow. Every code has a page in this documentation: E_OFF_MESH, all codes.

People

Changing who is on a goatnet takes operator authority.

goat admin holds the operator verbs. Each is authorized on the server by the person's own op_ operator key, which is never in an onboarding bundle; a participant's vp_ token gets E_NOT_ADMIN. Each action is recorded, and goat audit reads the record of who did what.

VerbWhat it does
admin inviteSponsors a candidate with a one-time onboarding invite: the first stage of the three-stage onboarding.
admin queueLists the onboarding proposals, then approves or rejects each one: the operator's gate.
admin onboard --revokeRevokes an operator or an org by handle: the offboarding path.
admin rotateReissues a peer's certificate in place: same anchor, same grants, a fresh leaf.
admin roleChanges an existing person's sign-in groups or activation, with the same guard and audit as the console.
admin operator-keyRequests and collects a person's own op_ key, so an admin action names a person.

Try it

Try it before you hold any credentials.

Download, check the checksum, and run the sandbox. Linux and macOS on amd64 and arm64, and Windows on amd64; each release lists a SHA-256 checksum per binary in SHA256SUMS, signed with cosign.

OS="$(uname -s | tr '[:upper:]' '[:lower:]')"; ARCH="$(uname -m | sed 's/x86_64/amd64/; s/aarch64/arm64/')"
base=https://github.com/usareur-af/goatcore/releases/download/goat-cli-v0.5.20
curl -fL --remote-name-all "$base/goat-$OS-$ARCH" "$base/SHA256SUMS"
shasum -a 256 -c --ignore-missing SHA256SUMS
install -m 0755 "goat-$OS-$ARCH" ~/.local/bin/goat
goat hello
goat tutor

When you are issued an onboarding bundle, attach the real goatnet. goat trusts no goatnet until you add the root that signed your bundle; check the fingerprint goat ca add prints against one your operator gives you.

goat ca add <bundle-ca.pem>
goat profile init <bundle.cbor>
goat init
goat doctor
