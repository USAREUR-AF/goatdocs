# Changelog, 13 to 16 November 2026: goatbuilder 0.7 builds a joining site with one command, and a fault on someone else's peer is measured

goatbuilder 0.7.0, 0.7.1 and 0.7.2 are published. With them, `goatbuilder join-node` builds a joining site with no manual step after the node is reached: it enrolls the node, issues its certificates, and deploys its data router, health publishers, front door and mesh DNS. A goatnet can also measure a fault on a peer it does not own, such as a clock that runs ahead or a client that refuses the router's certificate, and show it per peer. The whole-repository tag `goatcore/v0.7.1` is cut, and the branch `stable` points at it.

This entry covers all 33 public [USAREUR-AF](https://github.com/USAREUR-AF) repositories, because a change in one usually lands with matching changes in others. Seven of them opened in this window: [awesome-goat](https://github.com/USAREUR-AF/awesome-goat), [first-bite](https://github.com/USAREUR-AF/first-bite), [hello-galaxy-first-bite](https://github.com/USAREUR-AF/hello-galaxy-first-bite), [hello-galaxy-record-consumers](https://github.com/USAREUR-AF/hello-galaxy-record-consumers), [open-entity-gateway](https://github.com/USAREUR-AF/open-entity-gateway), [first-bite-env](https://github.com/USAREUR-AF/first-bite-env) and [goat-cloud](https://github.com/USAREUR-AF/goat-cloud) ([section 7](#7-learning-and-documents)). A new page, [`repositories.md`](https://github.com/USAREUR-AF/goatdocs/blob/main/docs/reference/repositories.md), lists every public repository with one line on what it is. The entry follows [the entry for 10 to 13 November](2026-11-13-one-command-federation-stable-line.md).

## In short

- **Install goatbuilder 0.7.2, and build on `goatcore/v0.7.1` or `stable`.** 0.7.0 gives every refusal a code and lets `join-node` build a joining site. 0.7.1 adds the site's mesh DNS, key rotation and both sides' acceptance. 0.7.2 adds `goatbuilder grow` and the rotation of an IPsec peering's credentials. Do not rotate a forwarder carrier key with 0.7.2 ([section 1](#1-releases)).
- **`goatbuilder join-node` builds a joining site, including its own mesh DNS.** Only reaching the node stops the run. The portal, the id console and the onboarding engine still run only at a goatnet's first site ([section 2](#2-one-command-builds-a-joining-site)).
- **A running peering's leaves can be rotated, and one command completes both sides' acceptance.** `goatbuilder federate rotate <partner> leaves` and `goatbuilder federate test <partner> --bilateral` are in 0.7.1. Neither is measured yet on a peering between two standing goatnets ([section 3](#3-federation-acceptance-by-both-sides-key-rotation-two-drivers-and-back-out)).
- **Backing a peering out removes the partner's data whole.** A partner's data lives in its own store, and the store is dropped when the peering ends. Where two peerings share an edge and a core, the back-out keeps what the other peering uses ([section 3](#3-federation-acceptance-by-both-sides-key-rotation-two-drivers-and-back-out)).
- **Every goatbuilder verb shows its work.** `standup`, `join-node`, `deploy` and `federate` list every value with its source, a failed phase carries its error code and fix, and each run is timed step by step ([section 4](#4-every-verb-shows-its-work)).
- **A fault on a peer you do not own is measured per peer.** `goat health --domain peer` shows which peer's clock is ahead ([section 5](#5-faults-on-peers-you-do-not-own)).
- **Every site of a goatnet will write, and the first site is its hub.** ADR 1165 and ADR 1205 are accepted. The guard that lets only the hub make a platform admin is built. Most of the design is not built ([section 6](#6-sites-that-run-cut-off)).
- **A goatlite can be handed over to the full preset.** `goatbuilder grow`, in 0.7.2, rewrites a goatlite's configuration into a full one with the same values. It changes the checkout and never a host ([section 7](#7-learning-and-documents)).
- **first-bite decodes binary messages from a link and can publish them to a goatnet.** Its release 1.1.0 is published, with a worked example, an example overlay and two companion repositories. goat-cloud, also new, keeps an owner, a purpose and a lifetime on every cloud resource. The documents also describe a moon pod as a learning tool ([section 7](#7-learning-and-documents)).
- **Workflows pin their actions by commit and start read-only.** The leak gate also reads the names of added and renamed paths ([section 8](#8-contributing-and-ci)).

## 2. One command builds a joining site

`goatbuilder join-node` used to stop twice for a person, and left the site's data router, certificates, health publishers and mesh DNS as steps done by hand. It now runs phases 1 to 15 in order and stops only at phase 1, where a person reaches the node.

## 3. Federation: acceptance by both sides, key rotation, two drivers and back-out

One command can now complete both sides' acceptance of a peering, and one command rotates a running peering's leaves. Backing a peering out removes the partner's stored data whole and leaves every other line of the core's configuration as it was.

| Change | What you see | PR |
|---|---|---|
| Both sides' acceptance in one command | `goatbuilder federate test <partner> --bilateral` runs phase 14 on a session both sides derive from the agreement. Each side signs its result, the result crosses the fabric, and the other side verifies it under the key bound at phase 5. It is opt-in, and phase 14 is unchanged without the flag. A combined PASS in which each side holds only its own surfaces is designed, and its build is in review (goatcore [#815](https://github.com/USAREUR-AF/goatcore/pull/815)) | goatcore [#654](https://github.com/USAREUR-AF/goatcore/pull/654), [#659](https://github.com/USAREUR-AF/goatcore/pull/659), [#719](https://github.com/USAREUR-AF/goatcore/pull/719), [#720](https://github.com/USAREUR-AF/goatcore/pull/720), [#752](https://github.com/USAREUR-AF/goatcore/pull/752), [#786](https://github.com/USAREUR-AF/goatcore/pull/786), [#789](https://github.com/USAREUR-AF/goatcore/pull/789), [#808](https://github.com/USAREUR-AF/goatcore/pull/808), [#791](https://github.com/USAREUR-AF/goatcore/pull/791) |
| Key rotation as a command | `goatbuilder federate rotate <partner> leaves` replaces a running peering's leaves, and a leaf rotation that was interrupted finishes or rolls back. `rotate <partner> carrier` is meant to rotate the forwarder carrier keys. In 0.7.2 it does not complete a carrier rotation, and the correction is in review (goatcore [#839](https://github.com/USAREUR-AF/goatcore/pull/839)). After a signing-key rotation, phase 5 hands the peering directory over to the new key, signed by the key it replaces, and prints GB-285 and publishes nothing when it cannot. ## About this entry

- **Window.** Pull requests merged from 13 November 2026 16:10 UTC to 16 November 2026 05:36 UTC, in every public USAREUR-AF repository.
- **What "merged" means here.** A change is described as part of goat only when it merged into a repository's default branch. A pull request merged into any other branch is reported as in review.
- **The weekly listing.** [`weekly/`](weekly/INDEX.md) lists every merged pull request by kind, one page per ISO week, generated with no person or model in the loop. Written entries explain; the weekly listing is the complete record.
